## 1. 产品概述

### 1.1 一句话定义

**CoLiv 是一款面向合租人群的轻量级协作管理工具，帮助室友间高效处理清洁轮值、公共物品登记、费用分摊和维修报修，用数字化的方式替代冰箱上的便利贴。**

### 1.2 产品愿景

让合租不再因为"谁该做什么"和"谁欠谁多少"而消耗关系。

### 1.3 核心价值主张

| 痛点 | 解决方式 |
|------|----------|
| 清洁分工靠口说，没人主动做 | 自动轮值 + 到期提醒 + 拍照打卡 |
| 公共物品谁买的算不清 | 快速登记 + 自动计入月度账单 |
| 水电费算起来麻烦 | 读数录入自动计算 + 不在场豁免 |
| 维修没人管、费用扯皮 | 报修工单流 + 费用自动分摊 |
| 月底算账一团乱 | 一张月度账单汇总所有项目 |

## 2. 目标用户

### 2.1 用户画像

| 画像 | 特征 |
|------|------|

## 4. 详细功能设计

### 4.1 房屋管理

#### 4.1.1 创建房屋
- 用户创建"房屋"，填写：房屋名称、地址（选填）、房间数
- 创建后获得邀请码 / 二维码 / 邀请链接

#### 4.1.2 成员加入
- 扫码或点击链接加入
- 填写：昵称、头像、入住房间号、入住日期
- 房主可设管理员权限（可编辑房屋设置）

#### 4.1.3 成员管理
- 成员列表：昵称、房间号、入住日期、角色
- 退租流程：标记退租日期 → 自动结算该成员应承担费用 → 确认离场
- 交接场景：退租时导出该成员的参与记录

#### 4.1.4 房屋设置
- 账单周期（每月几号出账）
- 清洁轮值周期（每周/每两周）
- 费用默认分摊方式（均分/按房间数/按人头）
- 通知偏好（站内推送 / 静默时段）

---

### 4.2 清洁轮值

#### 4.2.1 任务定义
- 预设清洁区域：厨房、卫生间、客厅、阳台、垃圾倾倒
- 每个区域可自定义子任务，例如厨房：灶台擦拭、油烟机、地面、冰箱清理
- 可设置任务频率：每日 / 每周 / 每两周 / 每月
- 可设置任务难度权重（用于公平性校验）

#### 4.2.2 轮值排班
- **自动轮值**：系统按成员列表自动分配轮值顺序，到期自动切换
- **手动调班**：成员间可发起换班请求，对方确认后生效
- **公平性看板**：显示每人累计完成次数、总权重，偏差过大时提醒

#### 4.2.3 提醒机制
- 轮值到期前1天推送提醒给当前负责人
- 过期未完成，第二天升级提醒（同时通知所有人）
- 提醒文案要"有温度不催命"，例如："该你倒垃圾啦 🗑️ 今天就是最后一天了"

#### 4.2.4 拍照打卡
- 完成清洁后上传1-3张照片
- 照片记录时间戳
- 其他成员可见，可"点赞"确认（避免检查感，强化正向反馈）
- 超过半数成员确认即标记为"已完成"

#### 4.2.5 清洁记录
- 历史记录列表：日期、区域、负责人、照片、确认状态
- 统计面板：本月每人完成次数、按时率、平均确认时间

---

### 4.3 公共物品

#### 4.3.1 消耗品登记
- 快速记账入口：选择品类（纸巾/洗洁精/垃圾袋/洗衣液...）→ 输入金额 → 选择分摊方式 → 完成
- 支持拍照留存小票
- 自动计入当月账单
- 低库存提醒：标记某物品"快用完了"，提醒下次采购人

#### 4.3.2 耐用品登记
- 登记：物品名称、照片、归属人（个人/公用）、购入时间、价格
- 标记"公用"的物品参与退租时的资产清算
- 标记"个人"的物品退租时带走，不参与分摊
- 搜索 & 列表视图，支持按归属人筛选

#### 4.3.3 采购轮值（可选 v2）
- 消耗品采购也可轮值，系统按消耗速度预测下次采购时间
- 采购人登记后自动分摊

---

### 4.4 费用分摊

#### 4.4.1 账单录入

**两种模式：**

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **读数模式** | 录入表读数，系统计算用量×单价 | 电费、燃气、水费 |
| **金额模式** | 直接输入总金额 | 宽带、物业费、固定费用 |

- 读数模式支持拍照留存表盘照片
- 支持设置阶梯电价（可选 v2）

#### 4.4.2 智能分摊

**分摊规则：**

| 规则 | 说明 |
|------|------|
| **均分** | 所有成员平均分担 |
| **按比例** | 自定义每人比例（如某人房间大，承担更多） |
| **按在场天数** | 根据本月实际在场天数分摊（出差/旅行自动豁免） |
| **豁免标记** | 手动标记某人本月不参与某项费用 |

**在场天数计算：**
- 成员可提前标记"不在场"日期段
- 系统自动计算实际在场天数
- 月度账单中自动按在场天数调整分摊比例

#### 4.4.3 结算台账
- 实时显示"谁欠谁多少"
- 支持手动标记"已转账"
- 推荐最优结算路径（减少转账次数）
  - 例：A欠B 50，B欠C 50，C欠A 50 → 三角债抵消，实际0转账

#### 4.4.4 月度账单
- 每月账单日自动生成，汇总：
  - 水电燃气费
  - 公共物品采购
  - 维修费用
  - 清洁完成情况（作为公平性参考）
- 账单以卡片形式呈现，清晰列出每人应付/已付
- 一键发起结算提醒（通知欠款人）

---

### 4.5 维修报修

#### 4.5.1 提交工单
- 入口：首页快捷按钮 → "报修"
- 填写：
  - 问题描述（文字）
  - 照片（1-3张）
  - 紧急程度（紧急/普通）
  - 涉及物品（关联耐用品登记，可选）
- 自动@所有人，进入待处理状态

#### 4.5.2 处理流转
```
已提交 → 已认领 → 处理中 → 已完成 → 待结算
                                         ↓
                                     费用登记 → 自动分摊
```
- 任何成员可"认领"工单
- 处理完成后上传修复照片，标记完成
- 如有费用产生，录入金额 → 选择分摊方式 → 计入当月账单

#### 4.5.3 历史记录
- 按时间线展示所有维修记录
- 可筛选：已解决 / 进行中
- 支持关联到耐用品（"这个洗衣机已经修了3次了"）

#### 4.5.4 定期维护提醒（v2）
- 可设置周期性维护任务（如：空调滤网每3月清洗、热水器年检）
- 到期自动生成提醒

---

### 4.6 公告板

#### 4.6.1 置顶消息
- 房主/管理员可置顶重要通知
- 例如："10月15日房东来检查"、"本周六停水"
- 支持设置到期时间，到期自动取消置顶

#### 4.6.2 访客通知
- 登记访客信息：来访人、时间、过夜/不过夜
- 自动通知所有室友
- 退租时清理

#### 4.6.3 房屋守则
- 可自定义规则，如：安静时间 23:00-07:00、厨房用完即清、吸烟去阳台
- 新成员加入时需确认阅读

### 4.7 首页 Dashboard

#### 4.7.1 信息架构
```
首页
├── 顶部：房屋名称 + 本月账单预览（应付/已付）
├── 本周待办
│   ├── 🧹 我的清洁任务（区域 + 截止日期 + 去打卡按钮）
│   ├── 🔧 待处理维修（如有）
│   └── 📦 待采购物品（如有低库存提醒）
├── 最近动态
│   ├── XX 完成了厨房清洁 ✓
│   ├── XX 登记了纸巾采购 ¥45
│   ├── XX 提交了维修工单
│   └── XX 标记10/1-10/5不在场
└── 快捷入口
    ├── 登记采购
    ├── 录入水电
    ├── 报修
    └── 查看月度账单
```

#### 4.7.2 设计原则
- 首页即"控制台"：打开就知道该干什么、欠多少、谁做了什么
- 信息密度适中，避免信息过载
- 动态feed用时间线，最多展示10条，更多可展开

## 5. 用户流程

### 5.1 新用户首次使用
```
注册/登录 → 创建房屋 → 填写房屋信息 → 邀请室友
→ 设置清洁区域 → 设置账单周期 → 进入首页
```

### 5.2 被邀请用户
```
扫码/点击链接 → 注册/登录 → 填写个人信息 → 加入房屋 → 进入首页
```

### 5.3 日常清洁流程
```
收到提醒（轮值到期）→ 查看任务详情 → 完成清洁 → 拍照打卡
→ 等待确认 → 标记完成 → 公平性看板自动更新
```

### 5.4 月度结算流程
```
账单日到达 → 系统自动生成月度账单 → 推送通知所有人
→ 各自查看明细 → 确认无误 → 发起结算
→ 标记已转账 → 结算完成
```

### 5.5 维修全流程
```
发现问题 → 提交工单（拍照+描述）→ 全员收到通知
→ 某人认领 → 联系维修/自行处理 → 修复完成上传照片
→ 登记费用 → 自动分摊 → 计入月度账单
```

## 6. 页面设计

### 6.1 设计原则
- **轻量**：核心操作不超过3步点击
- **友好**：不使用"管理""监督"等词，用"协作""打卡""帮忙"替代
- **游戏化**：清洁打卡有完成动画，公平性看板用进度条
- **移动优先**：以手机端为主，PC端为只读浏览

### 6.2 页面清单

| 页面 | 核心内容 | 关键交互 |
|------|----------|----------|
| 首页 Dashboard | 待办+账单+动态 | 卡片点击跳转 |
| 清洁中心 | 当前轮值+历史+公平看板 | 打卡、换班请求 |
| 公共物品 | 消耗品列表+耐用品列表 | 快速记账按钮 |
| 费用管理 | 账单列表+录入+结算台账 | 录入、标记已付 |
| 维修中心 | 工单列表+提单 | 提交、认领、完成 |
| 公告板 | 置顶+访客+守则 | 发帖、登记 |
| 房屋设置 | 成员+周期+规则 | 邀请、编辑 |
| 个人中心 | 头像+在场记录+通知设置 | 标记不在场 |

## 7. 数据模型（概要）

### 7.1 核心实体

```
House (房屋)
├── members[] → Member
├── cleaning_zones[] → CleaningZone
├── cleaning_records[] → CleaningRecord
├── shared_items[] → SharedItem
├── utility_bills[] → UtilityBill
├── repair_orders[] → RepairOrder
├── settlements[] → Settlement
├── monthly_bills[] → MonthlyBill
├── announcements[] → Announcement
└── visitors[] → Visitor
```

### 7.2 关键字段

**Member**: id, name, avatar, room_number, join_date, leave_date, role, absent_periods[]

**CleaningZone**: id, name, tasks[], frequency, difficulty_weight, current_assignee, rotation_order[]

**CleaningRecord**: id, zone_id, assignee_id, due_date, completed_at, photos[], confirmed_by[], status

**SharedItem**: id, type(consumable/durable), name, purchaser_id, price, split_method, photo, purchase_date, ownership

**UtilityBill**: id, type(electric/water/gas/internet), period, reading_before, reading_after, unit_price, total_amount, split_method, split_details[]

**RepairOrder**: id, title, description, photos[], urgency, status, claimed_by, resolved_at, cost, cost_split_method

**Settlement**: id, from_member, to_member, amount, related_month, status, paid_at

## 8. 技术方案建议

### 8.1 技术选型（Vibecoding 友好）

| 层 | 方案 | 理由 |
|----|------|------|
| 前端 | React + Next.js + Tailwind | 生态成熟，AI生成友好 |
| UI组件 | shadcn/ui | 复制粘贴式组件，可定制 |
| 状态管理 | Zustand | 轻量，适合中小型应用 |
| 后端 | Supabase / Appwrite | BaaS开箱即用，省去后端开发 |
| 数据库 | PostgreSQL (Supabase内置) | 关系型，适合分摊计算 |
| 认证 | Supabase Auth / Clerk | 手机号/微信登录 |
| 部署 | Vercel | Next.js原生支持，免费起步 |
| 存储 | Supabase Storage | 存清洁照片、小票 |

### 8.2 架构简图

```
┌─────────────────────────────────┐
│        Next.js (Vercel)         │
│   ┌──────┬──────┬──────┐       │
│   │ Pages│ API  │ Auth │       │
│   └──┬───┴──┬───┴──┬───┘       │
└──────┼──────┼──────┼───────────┘
       │      │      │
       ▼      ▼      ▼
  ┌────────────────────────┐
  │    Supabase / Appwrite  │
  │  ┌─────┬──────┬──────┐  │
  │  │Auth │  DB  │Storage│  │
  │  └─────┴──────┴──────┘  │
  └────────────────────────┘
```

### 8.3 关键技术考量
- **实时性**：清洁打卡、维修工单需要实时推送，用 Supabase Realtime
- **离线容错**：水电读数录入支持离线缓存，联网后同步
- **图片压缩**：清洁照片和小票在上传前压缩，控制存储成本
- **推送通知**：Web Push API + 移动端 PWA 推送

## 9. MVP 规划

### 9.1 MVP 范围（4-6周）

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P0 | 房屋创建 & 邀请加入 | 产品入口 |
| P0 | 清洁轮值 + 打卡 | 核心差异化功能 |
| P0 | 水电费录入 + 自动分摊 | 最高频使用场景 |
| P0 | 月度账单 + 结算 | 价值闭环 |
| P1 | 公共物品登记 | 高频但可简化 |
| P1 | 维修报修 | 完整链路但使用频率较低 |
| P2 | 公告板 | 锦上添花 |
| P2 | 公平性看板 | 数据需要积累才有意义 |
| P3 | 不在场豁免 | 复杂场景，初期手动处理 |

### 9.2 MVP 成功标准
- 一个房屋内有3-4人活跃使用
- 连续2个月完成月度账单结算
- 清洁打卡率 > 80%
- 用户次月留存率 > 60%

## 11. 竞品分析

| 竞品 | 优势 | 不足 | CoLiv 差异化 |
|------|------|------|-------------|
| Splitwise | 费用分摊成熟 | 只有费用，无清洁/维修 | 全场景覆盖 |
| 家务日历类App | 清洁排班 | 单机版，无合租协作 | 多人协作+轮值 |
| 微信群 | 人人都有 | 信息沉底、无结构化数据 | 替代群里的零散通知 |
| Notion/Excel | 灵活 | 需要手动维护，门槛高 | 开箱即用，自动化 |

## 12. 开放问题

| # | 问题 | 倾向 |
|---|------|------|
| 1 | 是否需要支持一人在多个房屋？（比如同时有合租+老家） | MVP不支持，v2支持 |
| 2 | 费用结算是否接入支付？ | MVP仅记账，不接入支付 |
| 3 | 清洁照片是否所有人可见？ | 默认可见，强化透明 |
| 4 | 是否需要数据导出？ | MVP支持CSV导出账单 |
| 5 | 房屋成员上限？ | MVP限制20人 |
| 6 | 是否需要多语言？ | MVP仅中文 |

## 13. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 室友不愿用 | 产品无法落地 | 降低门槛：PWA + 免下载 + 微信邀请 |
| 轮值公平性争议 | 用户流失 | 公平性看板 + 难度权重 + 换班机制 |
| 费用计算复杂 | 用户弃用 | MVP只做均分，逐步增加复杂规则 |
| 隐私顾虑 | 不愿上传照片 | 照片仅房屋内可见，可选择不拍照 |
